# Contributing to the P vs NP Page

Thank you for helping keep this catalog of P vs NP attempts alive!
This page continues the work of Dr. Gerhard J. Woeginger, who maintained
the original P-versus-NP page until his passing in 2022.

## What belongs here

Entries should be **notable attempts to settle the P vs NP question**, i.e.
papers, preprints, or public claims that:

- prove (or claim to prove) **P = NP**,
- prove (or claim to prove) **P ≠ NP**,
- argue the question is **undecidable** or **unprovable**, or
- are otherwise historically significant to the problem (major refutations,
  landmark barrier results, etc.).

A stable link must exist (arXiv, DOI, journal page, personal page, …).
Notability is judged loosely — Woeginger's original list ranged from
peer-reviewed work to usenet posts — but pure self-published spam may be
declined.

> **Important:** pull requests should add attempts to the *website* by creating
> a file under `data/attempts/` (see below) — not by appending to this README.

## Adding an attempt (the common case)

Each attempt lives in its own Markdown file in `data/attempts/`, so one PR
adds exactly one file and merge conflicts are rare.

### 1. Create the file

Name it `YEAR-firstauthor-short-topic.md`, e.g.
`data/attempts/2017-blum-solution-pvsnp.md`.
(Files sort alphabetically, so this naming keeps the site roughly chronological.)

### 2. Add front matter and a description

```markdown
---
id: blum-2017              # unique id; also used as the #anchor
claims: [not-equal]        # any of: equal, not-equal, undecidable, unprovable, other
year: 2017                 # publication year
authors: Norbert Blum      # optional but encouraged
title: "A Solution of the P versus NP problem"   # optional paper title
url: https://arxiv.org/abs/1708.03486            # optional primary link
status: retracted          # optional: refuted | retracted | withdrawn | disputed | accepted
---

One or two neutral paragraphs describing the approach and its outcome.
Links use regular Markdown: [arXiv:1708.03486](https://arxiv.org/abs/1708.03486).

Refutations and further reading belong here too, each with a link.
```

Guidelines for the description:

- Stay **neutral and factual** — describe what is *claimed*, not whether it works.
- Mention the status honestly (`refuted`, `retracted`, unresolved, …) and link
  refutations when they exist. This is what makes the page useful.
- Prefer permanent links (`https://arxiv.org/abs/...`, DOIs) over URLs that rot.
- Supported Markdown: paragraphs, `[links](…)`, `*italics*`, `**bold**`.
  No images, scripts, or raw HTML.

### 3. Rebuild the site

The site is fully static and generated by a zero-dependency Python script:

```sh
python3 build.py
```

This regenerates `docs/index.html`. Commit **both** your new file in
`data/attempts/` and the rebuilt `docs/index.html`.

```sh
git checkout -b add-my-attempt
python3 build.py
git add data/attempts/2017-example.md docs/index.html
git commit -m "Add Blum's 2017 P != NP attempt"
git push
```

Then open a pull request against `mikinty/P-vs-NP`.

### 4. Preview locally

```sh
python3 build.py && python3 -m http.server 8000 --directory docs
# open http://localhost:8000
```

## Other contributions welcome

- **Fixing broken links or typos** in existing files under `data/attempts/`
  (link rot is real — many entries are 20+ years old).
- **Updating an entry's status** when a claim gets refuted or retracted.
- **Improving the site itself.** Deliberately simple stack:
  - `build.py` — stdlib-only static site generator (no npm, no frameworks)
  - `assets/style.css` and `assets/app.js` — plain CSS/vanilla JS, copied
    verbatim into `docs/` at build time
  - `content/*.md` — static page sections
  Please keep this simplicity: if your change needs a dependency, it probably
  needs a very good justification.

## Code style

- Python: standard library only, type hints where cheap, no comments explaining
  obvious code.
- Run `python3 build.py` before committing so `docs/` stays in sync.
